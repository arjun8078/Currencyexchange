I researched three currency exchange services for our Angular + Django production use case (convert INR/local amounts to USD, AED, SAR, etc., including rate for a user-entered date):

1. Open Exchange Rates — https://openexchangerates.org/
2. ExchangeRate-API — https://www.exchangerate-api.com/
3. CurrencyAPI / community CDN-style feeds (used only for prototype comparison)

I also compared outputs against our reference pack (22/10/2026, 10,000 INR → ~105.43 USD / ~388.90 AED). Please see the attached FX_PROVIDER_RECOMMENDATION.pdf (and the earlier Currency Exchange screenshots).

Recommendation
I recommend Open Exchange Rates (paid) as our primary production provider.

Why Open Exchange Rates over ExchangeRate-API
- Historical / date-based rates are a first-class paid capability — important when bookings or invoices must use the FX of the selected date, not only today’s rate.
- Stronger production fit: App ID model, widely used in backends, clearer commercial licensing and ops maturity for a company product.
- Better alignment with audit needs: we can fetch a dated rate and store rate + rate_date + provider on each transaction.
- Multi-currency (INR, USD, AED, SAR) fits a standard USD-base pipeline in Django.

If price is the deciding factor
We can switch to ExchangeRate-API (paid). In our POC it felt close on USD/AED accuracy and is typically a bit cheaper. The codebase already supports a one-line env switch (FX_PROVIDER=exchangerateapi). I would treat that as the budget alternate, not the community CDN feeds (not suitable for production).

Code status
The repo default is now Open Exchange Rates. After you pull latest main locally, set OPEN_EXCHANGE_RATES_APP_ID in .env and run as documented in the README.
